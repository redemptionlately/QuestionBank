## 0. 三种电子书形态（用户唯一认可的形态，不要再造第四种）

| 形态 | 判型（SourceSniffer 自动打分） | 长什么样 | 入库结果 |
|---|---|---|---|
| ① 全文电子书 | `FULL_TEXT` | 出版社教材/讲义，有"第X章/第X节"结构 | book_kind=FULL_TEXT，章节进 sections 或正文 extractedText，图 fitz 插页 |
| ② 背诵电子书 | `RECITE` | 知识点集合 PDF/docx，"考点N：简述…" | book_kind=RECITE，一卡一题（title=问题，body=答案），手风琴展开 |
| ③ 题库/试卷 | `PAPER` | 真题卷 + 答案 | paper（bank 下），题目/选项/答案/解析四段齐全 |
| 扫描件 | `SCAN` | 纯图片 PDF/docx，零文字层 | 按页渲染成图翻页，**不做 OCR**（本机无 tesseract） |
| 大纲 | `SYLLABUS` | 考试大纲/考核目标 | 当正文，**绝不切成背诵卡** |

铁律：**绝不把知识点伪造成带假选项的试卷**；纯叙述性说明文绝不切成背诵问答卡。

## 1. 切分规则（已在解析器里定型，调接口即生效）

### 1.1 全文电子书（教材）
- **H1 = `第X章 / 第X篇 / 第X部分 / 第X讲`**，开独立节；**H2 = `第X节`**，开独立节。
  （2026-09-13 加`讲`：C 语言先修这类讲义按讲分章，pilot38 证据。）
- **H3 留在正文**：`知识点N`、`一、xxx`、`(1)(2)`、`本章重难点分析`、`重点：/难点：/例题`、
  `【答案】/【解析】` 都是正文段落，不立节。
- **目录行跳过**：连续 ≥3 个点线 `……` 加尾页码的行不是标题。
- **卷首印刷目录丢弃**：首个抬头之前的点线页码行 + bare `目录/目次` 直接丢，不进「前言」
  正文（正文里的 `……` shortening 不动，只限首抬头前；2026-09-13 pilot38）。
- **序言/前言/引言/凡例/封面 = 一级标题之前的正文**，落成一个「前言」节，绝不切问答。

### 1.2 背诵电子书（知识点集合）
**只有命中以下"真卡标题"才立卡**，其余一律并入上一卡答案正文：
- `【…】…`（方括号开头）
- `考点N：…` / `知识点N：…`
- `术语：定义` —— **冒号后必须同行有定义正文**才立卡；冒号在行尾的"引子句"（如
  `各阶段的基本目标为：`）归正文。
- 以问号 `？/?` 收尾的短行。

**绝不立卡（说明文）**：考试分析/考核目标/考核知识点与要求/试卷结构/考试方式/题型说明/
识记·领会·简单应用·综合应用/目录/封面/串讲开场白。无前置卡时归「前言」，有前置卡时并入当前答案。

**续段不立卡**：`(1)(2)(3)` 枚举、以 `为/是/如下/包括/：` 收尾的引子句、`（数字）` 子项，
都是上一张卡答案的续段。`(数字)` 短行不得被当排版碎片丢弃。
- **行注释/列表横杠不立卡**：`// 第二步` 这类代码注释、`- 主关键字` 这类横杠子项并入
  当前答案（2026-09-13 pilot46 实锤）。
- **NBSP 隐形空格**：PDF 抽出来的 ` `（strip 去不掉）先转普通空格，否则标题带隐形
  前缀（2026-09-13 pilot46 实锤）。
- **说明文归前言**：`适用对象/核心说明/内容简介/读者对象` 不立卡（2026-09-13 pilot46）。

### 1.3 题库/试卷
- 题目识别：`【单选/多选/填空/名词解释/简答/论述/应用题】` + 编号 + 选项 A/B/C/D。
- **答案块归属它前面那道题**；`答案：/解析：/【答案：】/【解析：】/答：` 抽成文字。
- 能抽成文字的答案**必须抽成文字，绝不存成图片**。
- 题型段（选择/填空/简答/名词解释/论述/应用）齐全，无选项的主观题（简答/填空）**不得丢弃**。

### 1.4 真题 + 答案文件配对（关键）
真题和答案常是**两个文件**，必须合成同一卷：
- 按文件名中的 **年份 + 月份 + 科目代码** 归并，如
  `2024年10月 自考 13005 软件工程 真题.docx` + `2024年10月 13005 软件工程 参考答案.docx`。
- 自含卷（题+答案+解析在一个文件里，如 `2026年4月…真题及答案.pdf`）直接整卷 parse。
- 用 `paper-pair` 端点对答卷**两路解析**：字母答题卡（`1.C`、`1-5 ABBCA`）映射选项文字，
  同时把答案文件当整卷再 parse 一遍抽简答/填空的文字答案，按题号合流，试卷自带答案优先。

## 2. 接口清单（extra 包，2026-09-12 实测）

登录：`POST /api/auth/login`，student/student123（只能读/答题），admin 口令见 AGENTS.md（写操作/上传要 ADMIN）。

| 用途 | 方法 + 路径 | 说明 |
|---|---|---|
| 预览解析（不入库） | `POST /api/ingest/parse?async=true` | 上传文件先看切分结果，人工核对后再 confirm |
| 异步任务轮询 | `GET /api/ingest/jobs/{jobId}` | async=true 时用 |
| 抽文本 | `POST /api/ingest/extract` | 抽文字层 |
| 导题成卷 | `POST /api/ingest/questions`（confirm） | body 含 bankName/paperTitle，题目成卷 |
| 导书 | `POST /api/ingest/book` | 全文书/背诵书入库 |
| **真题+答案配对预览** | `POST /api/ingest/paper-pair/preview` | 传真题+答案两文件，预览合一卷效果 |
| 书 sections 读取 | `GET /api/subjects/{sid}/books/{bid}/sections` | 背诵卡/章节列表 |
| 书 sections 全量替换 | `PUT /api/subjects/{sid}/books/{bid}/sections` | 改背诵卡标题/答案（全量回传，别丢其它卡） |
| 改名/回填正文 | `PUT /api/subjects/{sid}/books/{bid}` | body `{name}` 或 `{extractedText}`，ADMIN |
| 按页取扫描图 | `GET /api/subjects/{sid}/books/{bid}/images/{i}` | 扫描件翻页 / 正文插图 |
| 非选题合卷 | `GET /api/extra/questions?paperVersionId=` | STUDENT 可读；`POST .../bulk`/`DELETE .../{id}` 为 ADMIN |

> 约定：题目正文字段是 `q.prompt`（不是 `q.stem`）。增量键 = paperVersionId + 归一题干。

## 3. 推荐入库流程（每次都走 preview → 人工核对 → confirm）

1. **先探活**：`netstat` 看 8080 监听，`curl --noproxy '*'` 登录探针。
2. **preview**：调 `/api/ingest/parse` 或 `/api/ingest/paper-pair/preview`，**别直接入库**。
3. **核对预览输出**（这步不能省）：
   - 背诵册：第一张应是「前言」；后面每张都是真"考点N：…"；没有"考试题型说明/考核目标"假卡；
     没有续行（"各阶段的基本目标为："这种）被切成独立卡；每个考点答案枚举完整。
   - 全文书：章/节层级对；序言是正文；图按页插入。
   - 试卷：题目/选项/答案/解析四段齐；答案是文字不是图片；主观题没丢。
4. **confirm 入库**，然后**再调 GET sections / GET 题目复核一遍**（预览对 ≠ 入库对）。
5. **人工纠正**：切分不满意就用 `PUT .../sections`（背诵卡）或 `PUT .../book` 回填 `extractedText`
   （全文书正文）在线改；前端阅读器右上角铅笔按钮（ADMIN）直接编辑 Markdown。

## 4. 前端 .md 渲染与编辑（已实现）

- 电子书正文按 **Markdown** 渲染（`frontend/js/markdown.js` 的 `mdLite`/`mdInline`，先整段转义再白名单
  变换，XSS 安全）。支持 `#/##/###`、`**粗**`、`*斜*`、`` `码` ``、```围栏```、`-`/`1.`/`1）` 列表、
  `>` 引用、`---`、`![alt](url)`（后端相对图 `/api/.../images/{i}` 走带 Authorization 的 fetch→blob）。
- **在线编辑**：reader-bar 铅笔（仅 ADMIN）→ textarea 改 Markdown → 保存走 `PUT /api/subjects/{sid}/books/{bid}`
  回填 `extractedText`。背诵卡改 `PUT .../sections`（全量回传）。
- 用户改过后会写 prefs 旗标，重开不再被 `cleanFullText` 洗坏 Markdown。

## 5. 已知现实与坑（踩过即记）

- **2024/2025 自考真题 docx 是纯扫描图（零文字层）**：本机无 OCR，只能 fitz 按页渲染成图翻页，
  抽不出文字题。能文字化的代表样本是自含 PDF（如 2026 真题及答案.pdf）和带文字层的 docx。
- **扫描件不要硬抽文字**，直接 SCAN 成图。
- **老 `.doc`（Word 97-2003）**：后端抽不出文字时不要丢，先用 OLE 读 `WordDocument` 流
  （`output/doc39*.py` 链路，2026-09-14 book39 实锤）：单字节 ASCII 码段 + UTF-16LE 中文段
  按偏移合并（中文按偶数对齐，奇数偏移配对全是假字）；二进制内表按偏移整段切除（判据：
  8KB 窗口零合法行则整段不要，合法 = 文件名/代码关键词/干净中文）；`//`/横杠注释不立卡
  等背诵规则同样适用。无此链路就留 stub（sourcePath 指本地原件），不编造。
- **判重删书**：同一文件换名重复入库（如预算法真题 = 2024-10 真题逐字节相同，md5 证），
  备份后删后者（2026-09-14 book111，备份 `.workbuddy/backups/book111-dedup-*.sql`）。
- **上传上限两个都要设**：`SPRING_SERVLET_MULTIPART_MAX_FILE_SIZE`（单文件，默认仅 1MB）
  和 `MAX_REQUEST_SIZE`（总请求）都要 50MB；只设后者的话新起实例传 >1MB 直接 500
  （2026-09-13 8081 实锤，堆栈 `MaxUploadSizeExceededException`）。
- **preview 会落盘**：每次 preview 都在 `data/ingest-stage/` 留一份 UUID 副本，批量 preview
  后记得清（2026-09-13 起 124 个 375MB 的教训）。
- **8080/8081 双实例**：8080 是提权进程，本会话杀不掉；新码先发 `output/jars/qb-ui-dev.jar`
  跑 8081 验证，同库验证通过后再切 8080（需提权 kill）。
- 改 `?v=` 版本号文件内容必须同步 bump 版本号，否则浏览器跑旧字节。
- 后端新代码要重启 8080 才生效；多会话长跑验证用私有副本 `output/jars/qb-ui-dev.jar` 起在别的端口
  （如 8090），但数据写同一个 MySQL 3306，重启 8080 后即见。
- Flyway 新表开 V11+（本文档书写时已到 V10）；已应用迁移永不改。
- 严禁编造解析结果；每批入库留 preview/confirm JSON 证据到 `output/`。
