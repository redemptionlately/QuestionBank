# Java 后端 M0 教学路线

## 目标

本路线面向普通 Java 后端、业务后端、平台后端和基础设施后端岗位。目标能力不是背 API，而是能够把一个业务问题拆成：

```text
需求 -> 领域模型 -> HTTP 契约 -> Service 不变量
-> 事务/并发控制 -> SQL/索引 -> 错误与恢复
-> 测试证据 -> 面试表达
```

题库平台 M0 是真实业务载体，覆盖登录、角色、题库、版本发布、练习、判分、错题、事务、幂等、行锁、索引、Docker 和测试。
M1/M2 文件是后续 Java 后端可靠性和业务扩展知识，不代表项目已经实现。

## 两个文件的职责

每一天只有两个文件：

- `study.md`：只放学习内容。上半部分是必须背诵并能独立写出的定义、语法、代码骨架和源码片段；下半部分是MustUnderstand的调用链、数据流、不变量、事务、并发、故障边界、取舍和限制。
- `tests.md`：只放任务。上半部分逐项验收 `study.md` 的背写内容；下半部分是变式、故障注入、对照实验和面试追问。

## 源码索引规则

源码索引必须同时给出：

```text
文件 -> 类/方法/SQL 对象 -> 行号 -> 学习动作
```

例如：

- `PracticeService.java:52-85`：背写提交、锁定读取、判分和结果持久化主链路。
- `PracticeSessionRepository.java:11-16`：背写 `@Lock(PESSIMISTIC_WRITE)` 查询。
- `M0FlowIntegrationTest.java:178-210`：理解同 key 并发测试如何证明稳定结果，而不是只看测试通过。

项目源码链接使用相对于当天 `study.md` 的路径，确保 VS Code 预览可以直接打开。M1/M2 尚无对应项目源码时，索引指向具体官方类、API 或章节，并明确这是外部学习材料。

求职补强已嵌入原有天数：Day 01 Java 语言与 Stream，Day 04 I/O/NIO/序列化，Day 15 AOP 代理，Day 18 JDBC/MyBatis/连接池，Day 27 测试分层与 Testcontainers，Day 31 消息队列与 Outbox，Day 41 类加载与 GC，Day 42 JUC 同步器，Day 44 TCP/DNS/TLS/Linux，Day 49 Git/CI/CD/设计模式。

## 教学闭环

每一天按以下顺序推进，一次只推进一个小目标：

```text
提出问题 -> 用户复述 -> 学习具体知识
-> 用户写核心代码/伪代码 -> 运行聚焦测试
-> 用户解释真实输出 -> 做一个变式
-> 记录掌握等级和下一步
```

AI 可以提供骨架、提示、Review 和测试框架，但“编译通过”不等于用户掌握。只有用户能复述输入/输出/状态、亲手修改核心片段、解释测试结果并完成变式，才把对应模块记为 `learned`，否则只记为工程 `verified` 或“需复习”。

## 求职出口

完成路线不自动承诺 Offer。可投递的项目表述必须满足：

1. 能从 HTTP 请求追踪到 Controller、Service、Repository、SQL、事务提交和响应。
2. 能解释至少一个真实难点的失败边界、替代方案和测试证据。
3. 能亲手修改一个核心模块并通过聚焦测试。
4. 能区分 M0 已实现、日志已验证、尚未实现和未来设计。
5. 能把 Java 核心、Spring、MySQL、并发、测试和项目深度连接到业务问题，而不是只背框架名词。
